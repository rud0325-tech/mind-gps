# MindGPS 수정본 적용 안내

> **2026-10-11 기록·알림 수정본:** 이 파일의 아래 설명은 초기 수정본 안내입니다. 현재 학생·기기 지정, 교사 승인, 무료 알림 설정은 [최신 무료 운영 안내](FREE_OPERATION_20261011.md)를 확인하세요. 실제 배포 여부는 별도 검증 결과를 따릅니다.

이번 파일은 **수정한 전체 소스**입니다. GitHub 원본 저장소와 기존 AI Studio 공유·배포 앱에는 아직 반영하지 않았습니다. 새로운 유료 서비스나 결제 설정도 추가하지 않았습니다.

수정 기준은 `MindGPS_app`의 `1c83499` 버전이며, 확인한 원본 ZIP과 같은 코드입니다. 원본을 보관하고 수정본을 먼저 체험한 뒤 적용하는 순서를 권합니다.

## 먼저 체험 모드로 확인하기

수정본의 기본값은 **체험 모드(demo)** 입니다.

- Firebase 로그인·조회·저장과 Apps Script 전송을 하지 않습니다. 실제 시트나 교사 메일로 연결되지 않습니다.
- 체험 기록은 현재 열린 페이지 안에만 잠시 남고, 새로고침하면 사라집니다.
- ‘교사 체험’은 이 체험 기록을 보는 기능입니다. 실제 교사 계정 승인 절차를 시험한 것은 아닙니다.
- 현재 학습에는 포함된 문장·그림·음원을 사용하므로 Gemini API 키를 새로 넣을 필요가 없습니다.

설정 파일의 `VITE_DATA_MODE=demo`를 유지합니다. 해당 설정이 없어도 체험 모드로 열립니다. 기존 실행 환경에 `VITE_DATA_MODE=live`가 따로 설정되어 있다면 체험 전 `demo`로 바꾸고 미리보기를 다시 준비해야 합니다. 이미 만들어진 배포본은 설정 변경 후 다시 빌드·배포해야 반영됩니다.

## 전체 소스를 반영하는 방법

ZIP의 압축을 풀고 **`package.json` 파일과 `src` 폴더가 함께 있는 위치**를 기준으로 적용합니다.

`App.tsx` 한 파일만 바꾸면 동작하지 않습니다. 새 학습 화면, 소리 화면, 데이터 처리 파일이 서로 연결되어 있으므로 **폴더 구조와 파일 경로를 그대로 유지해 전체 수정본을 반영**해야 합니다. 기존 이미지·음원도 포함된 경로에 있어야 합니다.

**ZIP 파일 자체를 GitHub에 올리는 것만으로 앱 코드가 바뀌지는 않습니다. 압축을 푼 파일과 폴더를 반영해야 합니다.**

### 방법 1. GitHub에서 검토한 뒤 AI Studio로 가져오기

1. GitHub의 현재 원본을 보관합니다. 수정본은 먼저 별도의 검토용 브랜치에 반영합니다. 브랜치는 원본과 따로 변경을 확인하는 작업 공간입니다.
2. 압축을 푼 수정본의 파일을 같은 경로에 반영하고, 새 파일도 추가합니다. `src`, `docs`, 설정 파일 등이 한 단계 더 안쪽 폴더에 들어가지 않았는지 확인합니다.
3. 변경된 파일을 검토하고 체험 모드로 확인합니다. 이때 실제 학생 기록이나 기존 시트·메일 연결은 필요하지 않습니다.
4. AI Studio의 기존 MindGPS 앱에서 **Settings → GitHub**를 열어 어느 저장소와 연결되어 있는지 확인합니다. 검토한 변경이 그 연결 대상에 반영된 뒤, GitHub에서 바뀐 내용을 가져오는 기능을 사용합니다. 별도 검토 브랜치를 만들었다고 기존 앱이 자동으로 바뀌지는 않습니다.
5. AI Studio와 GitHub 양쪽에서 같은 파일을 수정해 충돌 화면이 나타나면 파일별 차이를 확인합니다. 기존 작업을 확인하지 않은 채 한쪽 전체를 덮어쓰지 않습니다.
6. AI Studio 미리보기에서 네 가지 활동과 체험 기록을 확인한 다음, 기존 공유·배포 앱에 적용하는 작업을 별도로 진행합니다.

Google 공식 문서는 Settings의 GitHub 탭에서 양방향 변경 반영을 지원한다고 설명합니다. 기존 앱과 별도로 시험하려면 Build 화면의 **Add files(+) → Import from GitHub**로 코드를 가져오는 방법도 있습니다. [Google AI Studio 공식 안내](https://ai.google.dev/gemini-api/docs/aistudio-build-mode)

### 방법 2. AI Studio의 Code 탭에서 파일을 직접 바꾸기

GitHub 연결을 사용하기 어렵다면 원본 앱의 코드와 현재 작업을 먼저 보관한 뒤, **Code 탭**에서 수정본을 반영할 수 있습니다. Code 탭의 직접 편집은 Google 공식 문서에서 안내하는 방법입니다. [Code 탭 편집 안내](https://ai.google.dev/gemini-api/docs/aistudio-build-mode)

이 경우에도 수정본과 같은 경로의 파일을 교체하고 새 파일을 추가해야 합니다. 예를 들어 `src/components/LearningActivity.tsx`와 `src/learning/content.ts`는 각각의 폴더 안에 있어야 합니다. 기존 캐릭터·배경 이미지·음원 경로도 유지합니다.

여러 파일과 폴더를 정확하게 반영하기 어렵다면 GitHub 경로를 이용하는 편이 수월합니다. 이 작업은 제공된 수정 파일을 반영하는 작업이므로, 앱 전체를 새로 생성하도록 프롬프트를 입력할 필요는 없습니다.

## 실제 수업 기록과 메일을 연결하기 전

체험 모드 확인 후 실제 운영을 연결할 때는 [데이터 운영 설정](DATA_SETUP.md)을 함께 봅니다. 필요한 작업은 다음과 같습니다.

1. **Firebase 프로젝트와 교사 권한 설정:** 사용할 프로젝트를 확인하고 학생의 익명 인증, 교사의 Google 로그인, 허용 도메인과 교사 승인 정보를 설정합니다.
2. **데이터 접근 규칙 배포:** 수정본의 `firestore.rules`를 실제 운영 대상에 별도로 배포하고 권한을 시험합니다. GitHub 파일을 바꾼 것만으로 운영 서버의 접근 규칙이 바뀌지는 않습니다.
3. **기존 Apps Script 원본 확인:** 이 저장소에는 Apps Script 서버 코드와 Gmail 발송 코드가 없습니다. 기존 원본과 배포 권한을 확인한 뒤 시트 저장, 메일 조건, 중복 처리 등을 함께 점검해야 합니다.
4. **시험 기록으로 연결 확인:** 시트에 실제로 기록됐는지, 교사 메일에 실제로 도착했는지 따로 확인합니다. 앱의 전송 시도만으로 시트 저장이나 메일 수신을 확정할 수 없습니다.
5. **운영 모드 반영:** 필요한 설정을 완료한 시험 환경에서 `VITE_DATA_MODE=live`를 적용하고 다시 빌드·배포합니다. 현재 수정본을 전달하는 작업에는 이 전환과 실제 배포가 포함되어 있지 않습니다.

현재 구조는 한 운영 프로젝트의 승인 교사들이 같은 기록을 보는 방식입니다. 여러 학교·학급의 기록을 서로 분리하는 기능은 아직 추가하지 않았습니다. 캐릭터도 실제 학생을 식별하는 번호가 아니므로, 캐릭터별 기록을 곧바로 학생별 장기 성과로 해석하지 않습니다.

- [ ] 앞 단계로 돌아가거나 다른 상황을 골라도 이전 선택이 잘못 섞이지 않는다.

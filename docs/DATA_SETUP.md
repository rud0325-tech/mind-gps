# MindGPS 데이터 운영 설정

> **2026-10-11 수정본 안내:** 아래는 이전 단계의 기록을 포함합니다. 이번 학생 지정·무료 긴급 알림 구조와 배포 순서는 [최신 무료 운영 안내](FREE_OPERATION_20261011.md)를 우선 확인하세요. 새 알림 경로는 Firestore 발송 상태를 확인하며 기존 무인증 Sheets 전송과 다릅니다.

2026-10-05 사용자 결정: 실제 저장·메일 연동은 앱이 어느 정도 완성된 뒤 진행합니다. Firebase(Firestore)를 원본으로 두고 Google Apps Script로 구글 시트에 정리하며, 부정 감정 5단계 또는 도움 요청 시 교사 이메일 알림을 연결하는 방향을 유지합니다. 실제 운영 주소·권한·발송 설정은 사용자가 추후 제공할 예정이므로 현재 연결이나 과금을 변경하지 않습니다.

현재 수정본은 **체험 모드(demo)** 입니다. Firebase 초기화·로그인·조회·저장과 Apps Script 전송을 하지 않습니다. 체험 기록은 열린 페이지의 메모리에만 보관하며(최대 2,000건, 교사 현황은 최근 100건) 새로고침하면 사라집니다. 교사 체험 버튼은 체험 기록 화면을 여는 용도입니다. 실제 Google Sheets와 Gmail에 연결하거나 과금·요금제를 변경하지 않았습니다.

기록을 읽고 해석하는 방법은 [교사 결과 기록 안내](TEACHER_OUTCOMES.md)를 참고합니다.

> **이 브랜치(`claude/live-edition`)는 실제 운영판입니다.** `app-mode.json`이 `live`라서 따로 설정하지 않아도 Firebase에 저장합니다. 새 AI Studio 앱에서 Firebase를 연결하도록 `firebase-applet-config.json`은 비워 두었습니다. 올리는 순서는 [AI Studio 실제 운영판 안내](AI_STUDIO_SETUP.md)에 있습니다. 아래 ‘현재 수정본은 체험 모드’ 설명은 체험판 기준입니다.

## 현재 확인할 수 있는 기능

모드는 `app-mode.json`의 `dataMode`(기본 `demo`)가 정하고, `VITE_DATA_MODE` 환경변수가 있으면 그 값이 먼저입니다. 둘 중 적용된 값이 정확히 `live`가 아니면 체험 모드입니다. `.env.local`을 만들 경우 `.env.example`을 복사하고 `VITE_DATA_MODE=demo`를 유지합니다. 네 가지 활동, 전후 감정·강도와 미응답, 중단 기록, 도움 요청, 교사 관찰 입력, 여섯 결과 지표, CSV 저장을 체험할 수 있습니다. 실제 학생 이름과 실제 교사 이메일은 필요하지 않습니다.

현재 앱은 미리 작성한 학습 자료와 포함된 이미지·음원을 사용합니다. Gemini API 키가 필요하지 않습니다. 운영 서비스의 현재 요금제나 계정별 한도는 이번 작업에서 확인하거나 변경하지 않았습니다.

## 실제 운영 전 필요한 설정

1. **프로젝트와 데이터베이스 확인**: `firebase-applet-config.json`이 운영하려는 Firebase 프로젝트와 데이터베이스를 가리키는지 소유자가 확인합니다. 설정의 공개용 API 키는 사용자 접근 권한을 대신하지 않습니다.
2. **Authentication**: Firebase 콘솔에서 Anonymous와 Google 로그인을 활성화하고 앱을 배포할 도메인을 허용합니다. 학생의 기록 쓰기는 익명 인증, 교사의 기록 읽기·처리는 Google 로그인과 별도 승인으로 구분합니다. 익명 UID는 학생 코드가 아닙니다.
3. **교사 승인**: 교사가 Google 로그인한 계정의 Firebase Authentication UID를 확인합니다. 소유자가 해당 데이터베이스에 `teachers/{UID}` 문서를 만듭니다. 이 문서의 존재가 승인 기준이며 앱에서 생성·변경·삭제할 수 없습니다. 다른 데이터베이스에 만든 승인은 적용되지 않습니다. 클라이언트는 자신의 승인 문서만 조회할 수 있습니다.
4. **규칙 배포와 시험**: `firestore.rules`를 실제 대상 데이터베이스에 별도로 배포해야 합니다. GitHub 파일 수정만으로 운영 권한이 바뀌지 않습니다. 시험 환경에서 비로그인 읽기 거절, 익명 사용자 읽기·수정 거절, 유효한 익명 쓰기 허용, 승인 교사의 조회·상태 처리·관찰 저장을 확인합니다. 잘못된 미응답 조합, 타인 UID, 학생이 보낸 교사 관찰, 기회 수를 넘는 자발적 요청 수 등도 거절되는지 확인합니다. 운영 규칙은 배포하지 않았습니다. 규칙 시험은 Firestore Emulator로 실행합니다(`npm run test:rules`).
5. **운영 모드 선택**: 위 설정을 마친 시험 배포에서만 `app-mode.json`의 `dataMode`를 `live`로 바꾸거나 `VITE_DATA_MODE=live`를 넣고 다시 빌드·배포합니다. Vite 환경변수는 빌드 시 반영됩니다. 별도의 시험 기록으로 저장·조회·교사 수정 과정을 확인합니다.

현재 권한 모델은 **반 담당 교사만 그 반의 기록을 보는 구조**입니다(아래 ‘반·학생 목록·기기 등록’). 기존 기록은 삭제하거나 일괄 변환하지 않습니다. 이전 기록도 승인 교사가 조회·처리하고 관찰과 학생 코드를 추가할 수 있습니다.

## 교사 화면과 기록 규칙 보호 (2026-10-10)

- **교사 로그인은 탭 단위로만 유지됩니다.** 학생용 익명 로그인과 교사 Google 로그인은 서로 다른 Firebase 앱 인스턴스를 사용합니다. 교사 로그인은 탭을 닫으면 끝나고(`browserSessionPersistence`), 교사가 로그인해도 학생 기기의 익명 ID가 바뀌지 않습니다.
- **교사 화면을 벗어나면 자동으로 로그아웃합니다.** 교사 로그인·기록 화면이 아닌 화면으로 이동하면 교사 세션을 끝냅니다. 학생 첫 화면의 "선생님" 버튼은 항상 다시 로그인을 요구합니다.
- **10분 동안 조작이 없으면 로그아웃합니다.** 공용 태블릿에 열린 교사 화면을 학생이 보는 일을 막기 위해서입니다.
- **학생 쪽에서는 `처리 완료` 상태의 기록을 만들 수 없습니다.** 확인 완료는 승인 교사만 할 수 있습니다.
- **불편한 감정(속상해요·화가나요·힘들어요) 강도 5가 담긴 기록은 반드시 `interventionNeeded: true`여야 저장됩니다.** 앱 검증과 Firestore 규칙에 모두 적용됩니다.
- **상태 변경 이력:** 교사가 상태를 바꾸면 `statusUpdatedBy`(교사 UID)와 `statusUpdatedAt`(서버 시각)이 함께 저장되며, 규칙이 두 값을 강제합니다. CSV에도 포함됩니다.
- **규칙 자동 시험:** `npm run test:rules`는 Firestore Emulator를 내려받아 실행한 뒤 `tests/rules/`의 권한 시험을 돌립니다. Java가 필요하며 실제 Firebase 프로젝트에는 연결하지 않습니다(`demo-mindgps` 가상 프로젝트).

## 반·학생 목록·기기 등록 (2026-10-10)

여러 선생님이 각자 자기 반 학생의 기록만 볼 수 있도록 반 단위로 나눕니다. 학생은 코드를 입력하거나 자기를 고르지 않고 캐릭터만 고릅니다.

| 저장 위치 | 내용 | 누가 쓰고 읽나 |
|---|---|---|
| `classes/{classId}` | 반 이름, 담당 교사 UID 목록(`teacherIds`, 최대 10명) | 승인 교사가 자기를 담당으로 만들고, 담당 교사만 읽고 수정 |
| `classes/{classId}/students/{code}` | **별칭**(20자 이내), 그림 표시, 표시 여부 | 담당 교사가 관리. 그 반에 등록된 기기도 읽기 가능. **실명 필드는 규칙으로 거부** |
| `devices/{학생 기기의 익명 UID}` | 반, 종류(`student` 학생 전용 / `shared` 교실 공용), 학생 코드(전용일 때), 기기 이름 | 담당 교사가 그 태블릿에서 로그인해 등록·해제. 기기는 자기 등록만 읽기 가능 |

- **누구 기록인지 정하는 방식(`identifiedBy`)**: 학생 전용 기기는 `device`, 교실 공용 기기에서 선생님이 활동 전에 고르거나 수업 시작 자리표로 정해지면 `teacher-before`, 나중에 학생 지정 대기나 교사 관찰 입력에서 고르면 `teacher-after`, 정하지 않으면 `none`. 규칙이 기기 등록과 반 학생 목록을 확인하므로 학생 화면에서 다른 학생 코드를 꾸며 넣을 수 없습니다. `symbol`(학생이 표시 카드로 선택)은 이후 선택 기능을 위해 예약해 두었습니다.
- 교실 공용 기기에서 선생님이 고른 학생은 **한 번의 활동이 끝나면 자동으로 지워집니다.**
- 등록하지 않은 기기의 기록은 `classId: null`, 학생 미지정으로만 저장되며, `teachers/{UID}` 문서에 `admin: true`가 있는 운영자만 볼 수 있습니다.
- 교사 화면은 한 번에 한 반의 기록만 불러옵니다(`where classId ==` + 최신순 100건). 이 조회에는 **복합 색인**이 필요하며 `firestore.indexes.json`에 정의했습니다. 규칙과 함께 `firebase deploy --only firestore`로 배포합니다.
- 기기 등록은 브라우저 저장소의 익명 로그인에 묶여 있어, 브라우저 기록을 지우거나 다른 브라우저를 쓰면 다시 등록해야 합니다. 등록 정보는 기기에 캐시하지만 저장할 때마다 서버 규칙이 실제 등록을 다시 확인합니다.

## 수업 시작·자리표·학생 지정 대기 (2026-10-10)

교실 공용 태블릿을 여러 반이 함께 쓰고, 학생이 코드를 입력하거나 자기를 고르기 어려운 경우를 위한 기능입니다.

- **자리표:** 교사 화면의 반 설정에서 교실 공용 기기마다 앉을 학생(별칭)을 정해 `classes/{classId}.seats`에 저장합니다. ‘빈자리’는 반만 정하고 학생은 비워 둡니다. 자리표는 최대 40대입니다.
- **수업 시작:** 교사가 휴대폰이나 교사 PC에서 ‘수업 시작’을 누르면 자리표에 있는 공용 기기 문서(`devices/{UID}`)에 `activeClassId`, `activeStudentCode`, `activeUntil`이 한 번에 저장됩니다. 각 태블릿은 자기 기기 문서를 실시간으로 지켜보다가 바로 그 반·그 학생으로 기록합니다(`identifiedBy: teacher-before`).
- **자동 해제:** 수업 시간은 40·50·90분 중에서 고르며, 규칙이 최대 4시간까지만 허용합니다. 시간이 지나거나 ‘수업 종료’를 누르면 태블릿이 원래 등록된 반으로 돌아갑니다. 다른 반 교사는 그 기기를 자기 반 수업으로 바꿀 수 있지만, 기기의 원래 반·이름·종류는 바꿀 수 없습니다.
- **규칙 확인:** 기록을 저장할 때 규칙이 기기 문서의 수업 상태를 다시 읽어, 수업 중인 반과 자리표의 학생 코드가 맞을 때만 저장합니다. 수업이 끝난 뒤에는 그 반 이름으로 기록할 수 없습니다.
- **학생 지정 대기:** 학생을 정하지 않고 남은 그 반 기록은 교사 화면 위쪽에 한 번의 활동(`sessionId`)씩 묶여 시간·태블릿·캐릭터와 함께 보입니다. 교사가 학생을 고르면 묶음 전체가 `identifiedBy: teacher-after`로 바뀌고, `learnerAssignedBy`(교사 UID)와 `learnerAssignedAt`(서버 시각)이 함께 저장됩니다. 확실하지 않으면 지정하지 않아도 되며, 지정하지 않은 기록은 반 전체 현황에만 쓰입니다.
- 공용 태블릿에서 학생이 직접 고르는 PIN·그림 빠른 선택은 만들지 않았습니다. 학생 전용 기기, 교사가 태블릿에서 직접 고르기, 수업 시작 자리표로 대신합니다.

## 기간 조회·관찰만 기록 (2026-10-10)

- **기간 조회:** 학생 성장 보고서는 `classId ==` + `createdAt` 기간 + 최신순으로 100건씩 나눠 읽습니다(규칙의 한 번 조회 100건 제한 유지). 기존 복합 색인(`classId`, `createdAt` 내림차순)을 그대로 씁니다. 한 번에 최대 1,000건까지 읽고, 넘으면 화면에 알립니다.
- **무료 한도와 읽기 수:** 보고서를 한 번 만들 때 그 기간 반 기록 수만큼 읽기가 생깁니다. 한 반 한 학기가 수백 건이면 Spark 요금제의 하루 읽기 50,000회 안에서 여러 번 만들어도 충분합니다. 학생을 바꿔 볼 때는 다시 읽지 않습니다.
- **관찰만 기록(`recordKind: observation`):** 담당 교사만 만들 수 있고, 반 학생 목록의 학생이 반드시 있어야 합니다. 감정·강도는 모두 `null`(이유 `not-asked`), `difficulty`는 `해당 없음`, `identifiedBy`는 `teacher-before`이며 `observationUpdatedBy`·`observationUpdatedAt`이 함께 저장됩니다. 규칙은 이 모양을 별도 경로로 확인해 학생 기기가 교사 관찰 기록을 만들 수 없게 합니다.

## 실제 모드 점검과 가상 Firebase 시험 (2026-10-10)

실제 모드(`live`)를 Firebase Emulator(가상 인증·데이터베이스)에 연결해 처음부터 끝까지 확인했습니다. 교사 승인 대기 → 승인 → 반 만들기 → 별칭 학생 3명 → 교실 공용·학생 전용 기기 등록 → 교사가 고른 학생·자리표 수업·학생 전용 기기로 기록 → 학생 지정 대기에서 나중에 지정 → 강도 5 도움 기록과 확인 완료 → 관찰만 기록 → 성장 보고서 → 다른 교사에게 보이지 않음까지 통과했습니다. 이 과정에서 체험 모드에서는 드러나지 않던 오류 두 가지를 고쳤습니다.

- **새 반의 학생 목록이 열리지 않던 문제:** 반을 만들면 서버 저장 확인 전에 화면이 그 반을 골라 학생 목록·기록을 열었고, 규칙이 아직 반을 볼 수 없어 거절했습니다. 이제 서버에 저장된 반만 목록에 나옵니다.
- **‘닫고 나가기’ 뒤 화면이 교사 로그인에 멈추던 문제:** 로그아웃이 먼저 끝나 화면이 로그인으로 바뀌는 중에 첫 화면으로 다시 바뀌면서 멈췄습니다(‘처음으로’도 듣지 않음). 이제 첫 화면으로 먼저 이동한 뒤 로그아웃합니다.

함께 넣은 운영 도움 기능입니다.

- **연결 점검:** 실제 모드의 ‘선생님 확인’ 화면에 ‘연결 점검’ 버튼이 있습니다. 연결 정보(`firebase-applet-config.json`)가 채워졌는지, 학생 기록용 익명 로그인이 켜졌는지, 이 앱의 `firestore.rules`가 배포됐는지를 확인합니다. 규칙 확인은 `rulesVersion/{버전}` 경로를 읽어 봅니다. 이 경로는 문서가 없고 읽기만 허용되며, 버전은 `src/lib/liveSetupCheck.ts`의 `RULES_VERSION`과 규칙 파일이 같아야 합니다(단위 시험이 확인).
- **연결 정보가 비어 있을 때:** 실제 모드인데 연결 정보가 비어 있으면 학생 화면 왼쪽 위에 빨간 ‘기록 저장 연결 필요’가 보이고, 교사 로그인은 연결 안내를 보여 줍니다.
- **승인 대기 계정 번호:** 승인 문서가 없는 교사가 로그인하면 계정 번호(UID)와 복사 버튼이 나옵니다. 운영자는 이 번호로 `teachers/{UID}` 문서를 만듭니다.
- **색인 안내:** 반 기록이나 기간 기록을 불러올 때 복합 색인이 없으면 Firebase가 알려 주는 색인 만들기 링크(`console.firebase.google.com`만 허용)를 교사 화면에 보여 줍니다.
- **Google 계정 선택:** 교사 로그인 창은 항상 계정 고르기를 보여 줍니다. 학생 태블릿을 등록한 뒤에는 그 브라우저의 Google 계정 로그아웃을 안내합니다. Google 계정이 남아 있으면 학생이 계정을 고르기만 해도 교사 화면에 들어올 수 있기 때문입니다.
- **학생 추가 칸:** 학생을 한 명 추가해도 입력 칸이 닫히지 않아 여러 명을 이어서 넣을 수 있습니다.

가상 Firebase로 직접 확인하려면 Java가 필요합니다.

```bash
npx firebase-tools@15.31.0 emulators:start --only auth,firestore --project demo-mindgps
VITE_DATA_MODE=live VITE_FIREBASE_EMULATOR=true npm run dev
```

`VITE_FIREBASE_EMULATOR=true`로 만든 빌드는 실제 프로젝트가 아닌 `demo-mindgps` 가상 프로젝트에만 연결하고, Google 로그인 창 대신 가상 계정(`teacher@example.com`)으로 들어갑니다. 운영 빌드에는 이 값을 넣지 않습니다. 가상 데이터베이스는 복합 색인을 검사하지 않으므로 색인은 실제 프로젝트에서 따로 확인해야 합니다.

## 기록 구조

새 활동 기록의 `schemaVersion`은 `2`입니다. 이전 기록과 함께 읽되, 이전 방식의 기본 강도와 실제 선택 여부를 확인할 수 없으므로 이전 기록은 새로운 감정 전후 비교에서 제외합니다.

| 구분 | 주요 저장 항목 | 원칙 |
|---|---|---|
| 식별·출처 | `eventId`, `sessionId`, `classId`, `learnerCode`, `identifiedBy`, `schemaVersion`, `appVersion` | 학생 코드는 교사가 정한 별도 코드이며 캐릭터·기기·익명 UID에서 추정하지 않음 |
| 활동 | 캐릭터 ID·이름, 학습 방법, 활동명, `recordKind`, `activityOutcome`, `completed`, `practiceSummary` | 활동·도움·기분 확인을 구분하고 연습 문장을 실제 현재 감정과 분리 |
| 학생 자기보고 | 전후 감정·강도, 각각의 미응답 이유 네 항목 | 명시적 선택만 저장, 미응답은 `null`, 이유 없이 0이나 3으로 대체하지 않음 |
| 도움·확인 | `helpRequested`, `interventionNeeded`, `status`, `alertTrigger` | 학생의 도움 버튼과 불편한 감정 강도 5의 자동 알림을 구분 |
| 교사 관찰 | 실제 사용/연습 맥락, 요청 기회·자발적 요청, 지원 수준·제공 결과, 행동 정의·빈도·지속시간, 관찰·참여시간, 장소·상대 역할, 입력 지원, 메모 | 교사가 별도 입력하며 학생 원응답은 수정하지 않음 |
| 저장·수정 이력 | `createdAt`, `createdBy`, `observationUpdatedAt`, `observationUpdatedBy`, `statusUpdatedAt`, `statusUpdatedBy`, `learnerAssignedAt`, `learnerAssignedBy` | 서버가 기록 시각·인증 UID를 지정, 교사 관찰 수정은 승인 교사만 가능 |

`learnerCode`는 반 학생 목록의 코드(예: `S01`) 또는 `null`입니다. 학생 전용 기기는 등록된 학생 코드를 자동으로 붙이고, 교실 공용 기기는 선생님이 고른 학생 코드를 한 번의 활동에만 붙이거나, 수업 중에는 자리표의 학생 코드를 붙입니다. 코드 없는 기록을 같은 학생의 연속 기록으로 묶지 않습니다. 실제 이름과 코드의 대응표가 필요하면 앱 밖에서 별도로 관리합니다.

감정이 없으면 강도도 `null`입니다. 감정만 선택하고 강도를 생략하는 부분 응답은 허용합니다. 값이 있으면 해당 미응답 이유는 `null`, 값이 없으면 `not-asked`·`unsure`·`skipped`·`interrupted`·`unconfirmed` 중 하나를 함께 기록합니다. 상세 해석과 분모는 [교사 결과 기록 안내](TEACHER_OUTCOMES.md)에 정리했습니다.

## Firebase·Sheets·메일 연결의 현재 범위

사용자가 이전에 운영한 Apps Script → Google Sheets 저장·메일 알림의 **원본 스크립트, 실행 주소, 배포 권한, 수신 교사 설정은 확인하지 못했습니다.** 이 로컬 수정본이 기존 운영 저장소와 이미 연결됐다는 뜻이 아닙니다.

현재 코드에서 `live`가 설정된 경우의 생성 경로는 **Firebase 인증 → Firestore 저장 확인 → 설정된 Apps Script 주소로 전송**입니다. Firestore 저장을 확인하지 못하면 Sheets 전송을 시작하지 않습니다.

- `VITE_GOOGLE_SCRIPT_URL`이 비어 있으면 Sheets 전송을 하지 않습니다. 기본값은 공란입니다. 이전 고정 전송 주소는 사용하지 않습니다.
- 새 `makeSheetPayload`는 캐릭터 ID, 학습 방법, 활동명, 완료·상태·확인 필요, 사건·회기 ID, 전후 감정·강도, 네 미응답 이유, 기록 종류·완료/중단, 학생 코드, 앱 버전, 알림 발생 이유, **연습 문장 요약**을 포함합니다. 전달받은 기록에 교사 관찰이 있으면 그 관찰도 포함합니다.
- **`deviceInfo`는 제거했습니다.** 브라우저·화면 크기 등 기기 지문, 인증 UID, 캐릭터 이름은 이 전송 자료에 넣지 않습니다. 학생 이름·연락처를 별도로 수집하는 필드도 없습니다. 연습 문장·메모에 개인 정보를 직접 입력하면 그 내용은 기록에 포함될 수 있으므로 코드와 관찰 사실 중심으로 기록합니다.
- 관찰을 포함할 수 있는 전송 자료 형식과 자동 동기화는 별개입니다. **현재 교사 관찰·학생 코드의 사후 수정과 ‘확인 완료’ 처리는 Firestore에만 저장되며, 기존 Sheets 행에는 반영되지 않습니다.** 완전한 양방향·수정 동기화는 이번에 구현하지 않았습니다. 현재 최신 교사 관찰을 포함한 자료는 교사 화면의 CSV로 저장할 수 있습니다.
- CSV는 승인 교사가 보는 전체 기록을 내보내므로 생성자·관찰 수정자 ID와 수정 시각도 포함합니다. 이는 계정 UID를 제외한 Apps Script 전송 자료와 범위가 다릅니다. CSV는 선택한 학생·활동 필터와 최근 조회 범위에 한정됩니다.
- 전송 주소를 설정하기 전에 실제 Apps Script가 새 필드 이름, `null`, 중첩 관찰 자료를 처리하는지 점검해야 합니다. 기존 스크립트가 추가 항목을 자동으로 새 열에 저장하는 것은 아닙니다.

## 도움 버튼·감정 강도 알림

현재 앱은 학생의 **도움 요청 버튼**과 전후 **불편한 감정(속상함·화남·힘듦)의 강도 5 선택**을 도움 기록으로 구분해 남깁니다. `alertTrigger`는 각각 `help-button`, `negative-intensity`입니다. 기분 좋음·편안함의 강도 5는 자동 도움 알림으로 처리하지 않습니다. 자동 알림 기록의 `helpRequested`가 `true`여도 자발적인 의사소통 횟수로 해석하면 안 됩니다.

메일은 앱의 도움 기록만으로 수신을 보장하지 않습니다. 실제 발송에는 기존 Apps Script의 실행·메일 권한과 수신 교사, 서버 측 조건이 필요합니다. 서버에서는 전후 감정 값과 알림 발생 이유를 검증하고, 같은 사건의 재시도와 활동 완료 기록 때문에 메일이 반복 발송되지 않도록 처리해야 합니다.

현재 전송은 `no-cors`이므로 브라우저가 수신 서버의 처리 결과를 읽을 수 없습니다. 응답이 돌아와도 `unverified`이며 **시트 저장·Gmail 발송·교사 수신 성공을 뜻하지 않습니다.** 전송은 8초 뒤 기다림을 끝내지만, 시간 초과 후 서버에서 처리될 가능성은 남습니다. 학생은 가까운 교사에게 직접 도움을 알릴 수 있어야 합니다.

## 저장 결과와 재시도

`saveActivityRecord`와 `requestHelp`는 `{ id, mode, sheetStatus }`를 반환합니다. `sheetStatus`는 `not-configured`, `unverified`, `failed` 중 하나입니다. `live` 결과가 반환되면 Firestore 쓰기는 서버 확인을 받았지만, Sheets·메일 확인과는 별개입니다.

Firebase 인증과 쓰기는 합쳐서 15초 안에 확인되지 않으면 `OperationUnconfirmedError`를 반환합니다. 이는 실패 확정이나 요청 취소가 아닙니다. SDK의 쓰기가 나중에 반영될 수 있으며, 이때 Sheets 전송은 추가로 시작하지 않습니다.

같은 열린 페이지에서 같은 `eventId`로 동시에·반복 제출하면 하나의 작업과 결과를 공유합니다. 서버 문서 ID도 인증 UID와 `eventId`로 정해집니다. 서버가 저장했는데 응답을 잃은 뒤 재시도하면, 기존 문서 수정 권한이 없는 익명 사용자에게 권한 오류가 발생할 수 있습니다. 새 ID로 무작정 재전송하지 말고 승인 교사가 기록을 확인해야 합니다. 서버의 Sheets 처리에도 별도의 중복 방지가 필요합니다.

앱 안에서 명시적으로 뒤로 가기·다른 화면 이동을 하면 완료 또는 중단 기록을 남깁니다. 브라우저를 강제로 닫거나 통신이 끊어진 모든 경우의 저장을 보장하지는 않습니다.

## 이후 통합 저장소 구성 시 권장 방식

학생 브라우저가 교사 관찰의 작성자나 메일 수신자를 직접 지정하지 않게 하고, 신뢰할 수 있는 서버가 Firestore의 권한 확인된 기록을 읽어 Google Sheets의 같은 사건 행을 추가·갱신하는 방식이 적절합니다. 사건별 중복 방지, 갱신 시각, 재시도 상태, 메일 발송 여부를 서버에서 관리해야 합니다. 이 서버 연동은 이번 변경에 포함되지 않았습니다.

Firebase의 Firestore 이벤트는 중복 전달과 순서 변경이 가능하므로, 향후 이를 사용할 때 같은 사건을 여러 번 처리해도 결과가 중복되지 않도록 설계해야 합니다. [Firebase Firestore 이벤트 공식 안내](https://firebase.google.com/docs/functions/firestore-events)

Apps Script의 실행·메일 한도는 계정 유형에 따라 다르고 변경될 수 있습니다. 실제 운영 계정과 예상 전송량을 기준으로 확인합니다. [Google Apps Script 할당량 공식 안내](https://developers.google.com/apps-script/guides/services/quotas)

Cloud Functions 등의 별도 서버를 선택한다면 배포 요건·결제 설정을 먼저 확인해야 합니다. 이 문서는 서버 선택 제안이며, 결제 연결·요금제 변경·서비스 배포를 수행한 것이 아닙니다. [Firebase Functions 시작 안내](https://firebase.google.com/docs/functions/get-started)

## 조회·운영 제한과 검증 범위

### 오늘의 긍정 메시지의 별도 이용

활동 선택 화면의 ‘오늘의 긍정 메시지’는 학습 활동과 분리된 선택 기능입니다. 입장·다시 뽑기·돌아가기는 활동 시작/완료/중단 기록을 만들거나 감정 응답을 바꾸지 않습니다. 별도 이용 횟수와 메시지 뽑기 횟수만 익명의 탭 메모리에 집계하며, 학생 정보·감정·메시지 내용을 저장하거나 외부 전송하지 않습니다. 교사 화면에서 이 임시 합계를 따로 볼 수 있습니다. 새로고침하면 초기화되고 학생·활동 필터, 학습 완료 수, 전후 감정 지표, CSV와는 무관합니다. 향후 교사 저장소를 연결할 때에도 이용 사건과 학습 결과를 구분해야 합니다.

아래 제한은 기존 학습 기록 조회에 관한 내용입니다.

- 교사 로그인 승인 후 **최근 100건**만 조회합니다. 학생·활동 필터, 그래프, CSV도 그 안에서 계산하며 전체 기간 통계가 아닙니다. 도움·기분 확인도 이 100건에 포함되므로 활동만 100회가 아닙니다.
- 학생 자기보고·연습 내용·교사 관찰을 구분합니다. 관찰 그래프의 날짜는 관찰 입력 시각이 아니라 연결된 활동 기록 시각입니다. 해당 활동 당시의 관찰을 입력합니다.
- 교사 로그인은 탭 단위로만 유지되고 교사 화면을 벗어나거나 10분 동안 조작이 없으면 로그아웃됩니다. 그래도 공용 기기에서는 작업 후 '닫고 나가기'로 로그아웃하는 것을 권장합니다. Firestore 학습 기록의 기기 내부 영구 캐시는 설정하지 않았습니다.
- 익명 인증만으로 악성 대량 제출까지 막을 수는 없습니다. 실제 배포의 App Check·사용량 제한·관측 설정은 수행하지 않았습니다.

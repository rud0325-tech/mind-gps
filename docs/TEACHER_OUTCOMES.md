# MindGPS 교사 결과 기록 안내

MindGPS는 학생의 전후 자기보고와 연습 내용, 교사 관찰을 함께 저장하되 서로 다른 출처로 보여 줍니다. 감정을 선택하지 않아도 활동 기록은 남습니다. 점수 하나를 ‘개선도’로 바꾸기보다, **응답이 얼마나 모였는지와 실제 생활에서 필요한 표현·지원이 어떻게 달라졌는지** 함께 살펴보는 화면입니다.

현재는 체험 모드이며 새로고침하면 체험 기록이 사라집니다. 운영 연결과 Google Sheets 동기화 범위는 [데이터 운영 설정](DATA_SETUP.md)에 정리했습니다.

## 기록을 남기는 순서

1. 교사 화면에서 반을 만들고 학생을 별칭으로 추가합니다(코드 `S01` 등은 자동). 학생 전용 태블릿은 그 학생으로 등록하고, 교실 공용 태블릿은 ‘다음 활동을 할 학생’을 고른 뒤 건넵니다. 캐릭터는 학생 식별자가 아닙니다. 공용 기기에서 고른 학생은 한 번의 활동이 끝나면 지워집니다.
2. 학생이 활동 전 감정과 강도를 선택합니다. ‘모르겠어요’ 또는 ‘선택하지 않을래요’도 기록할 수 있으며, 강도는 자동으로 3이 선택되지 않습니다.
3. 활동을 진행합니다. 나전달법·생각 바꾸기에서 고른 문장은 ‘연습 내용’으로 남고 현재 감정으로 바뀌어 저장되지 않습니다.
4. 활동 후 동일한 방식으로 감정과 강도를 확인합니다. 질문에 답하지 않아도 완료·미응답 기록은 남습니다. 명시적으로 활동 중 다른 화면으로 이동한 경우에는 중단을 구분합니다.
5. 교사가 해당 활동·도움 요청 당시의 관찰을 별도로 입력합니다. 이후 다른 날에 관찰한 사실을 과거 기록의 관찰로 입력하지 않습니다. 같은 회기의 관찰은 한 기록에만 입력합니다. 원래 학생이 선택한 감정 값은 그대로 유지됩니다.

학생이 그림을 가리키거나 시선으로 선택하고 교사가 화면을 눌렀다면 ‘학생 응답 · 입력 지원’입니다. 교사가 표정을 보고 추측한 감정은 학생 자기보고 값으로 대신 입력하지 않고 교사 관찰 메모에 남깁니다.

## 완성 응답·부분 응답·미응답

각 시점에 감정과 강도를 모두 선택해야 ‘응답 완성’입니다. 새 방식의 기록(`schemaVersion: 2`)에서 다음과 같이 구분합니다.

| 기록 상태 | 저장과 해석 |
|---|---|
| 전후 감정·강도 모두 선택 | 전후 비교 대상. 같은 감정의 강도 변화와 서로 다른 감정으로의 전환을 나눠 표시 |
| 활동 전만 완성 | 활동 전 상태를 알 수 있음. 사후 상태가 완성되지 않았으므로 전후 비교에서 제외 |
| 활동 후만 완성 | 활동 후 상태만 확인. 사전 상태가 완성되지 않았으므로 전후 비교에서 제외 |
| 두 시점 모두 미완성 | 어느 시점도 감정·강도 쌍이 완성되지 않음. 반드시 ‘아무것도 응답하지 않음’을 뜻하지는 않음 |
| 감정만 선택, 강도 생략 | 부분 응답. 감정 정보는 보존하지만 수치 비교에서 제외 |
| 둘 다 생략 | 두 값을 `null`로 저장하고 각각의 이유를 보존. 0점이나 보통 3점으로 채우지 않음 |

화면의 ‘감정·강도 일부만 응답한 활동’ 수는 위 네 완성 여부 분류와 **겹치는 추가 정보**입니다. 네 분류 수에 다시 더하지 않습니다. 미응답 이유는 ‘질문하지 않음’, ‘모르겠어요’, ‘선택하지 않을래요’, ‘활동 중단’, ‘이유 미확인’입니다. 알 수 없는 이유를 교사가 추정해서 채우지 않습니다.

이전 방식 기록은 기본 강도와 명시적인 선택 여부를 구분할 수 없어 새 감정 전후 비교에서 제외합니다. 이전 활동의 교사 관찰은 별도 출처이므로 조건이 맞으면 관찰 지표에 포함할 수 있습니다. 도움 알림·기분 확인 기록은 활동 분모에서 제외합니다.

## 여섯 지표와 계산 기준

교사 관찰 지표 2~6은 **‘생활 속 실제 사용’으로 교사가 명시적으로 입력한 관찰**만 사용합니다. 도움·기분 확인 기록에 추가한 관찰도 포함하며, 해당 기록 자체는 감정 전후 비교의 활동 분모에 포함하지 않습니다. ‘앱·수업의 연습’과 ‘미기록’은 보존하지만 실제 사용 지표에 합치지 않습니다. 비어 있는 항목은 해당 계산에서 제외합니다.

| 지표 | 화면의 수치와 분모 | 해석할 때 확인할 점 |
|---|---|---|
| 1. 학생이 보고한 감정 변화 | 새 방식 활동 중 전후 감정·강도가 모두 있는 활동 수. 같은 감정은 강도 낮아짐·같음·높아짐의 횟수, 다른 감정은 전환별 횟수 | 낮아짐을 자동으로 개선이라 부르지 않음. 편안함이 높아지는 경우도 있으므로 감정 종류와 함께 읽음 |
| 2. 스스로 필요한 것을 표현하기 | 자발적 요청 수의 합 / 요청 기회 수의 합. 기회 수가 1 이상이고 자발적 요청 수가 확인된 실제 사용 관찰만 포함 | 1/8 → 5/8처럼 분모와 조건을 함께 비교. 카드 누르기·자동 강도 알림은 실제 자발적 요청 수가 아님 |
| 3. 표현에 필요한 지원의 변화 | ‘힌트 없이 스스로·말 힌트·시범·함께 수행’별 **관찰 기록 건수**와 최근 기록 순서 | 미기록·관찰하지 못함은 제외. 순서형 지원을 임의의 평균 점수로 만들지 않음. 같은 표현·상황에서 비교 |
| 4. 요청이 실제 도움으로 연결되기 | 필요한 지원 제공 건수 / 제공·일부 제공·제공하지 못함이 확인된 관찰 건수 | ‘요청 없었음’과 미기록 제외. 한 관찰 기록은 여러 요청 각각의 결과를 세는 자료가 아님 |
| 5. 생활 속 행동과 참여 | 같은 행동 정의별 **횟수 / 관찰시간(분)**, 총 지속시간(초), **참여시간 / 관찰시간 × 100** | 관찰시간이 0 또는 미기록이면 시간당 빈도·참여 비율 계산에서 제외. 지속시간은 관찰시간 정보와 함께 확인 |
| 6. 다른 상황·상대에게도 사용하기 | 기회 수가 확인되고 자발적 요청이 1회 이상인 실제 사용 관찰의 **서로 다른 장소·상황 수와 상대 역할 수** | 성공률의 분모가 없는 종류 수이며 일반화의 증명이 아님. 같은 장소·역할은 같은 명칭으로 입력 |

요청 기회가 0이면 자발적 요청 0을 사실대로 남길 수 있지만 요청 비율을 계산하지 않습니다. 기회 수가 미확인인데 자발적 요청 수만 입력하는 것도 허용하지 않습니다. 자발적 요청 수는 기회 수보다 클 수 없습니다. 행동 지속시간과 참여시간은 전체 관찰시간을 초과할 수 없습니다.

**0과 미기록은 다릅니다.** ‘10분 동안 관찰했고 목표 행동이 없었음’은 행동 0회·관찰 10분입니다. 관찰하지 못했다면 행동 빈도·지속시간을 비워 둡니다. 지원 수준도 ‘관찰하지 못함’을 고를 수 있습니다. 수치가 없다는 이유로 그래프에 0을 채우지 않습니다.

## 그래프를 읽는 방법

- 그래프와 최근 관찰 목록은 연결된 **원본 기록 시각**을 기준으로 정렬합니다. 교사가 관찰을 나중에 입력해도 그 입력 날짜로 원본 기록 날짜가 바뀌지 않습니다. 관찰의 마지막 수정 시각과 수정자는 별도 필드에 저장합니다. 모든 수정 버전을 보존하는 변경 이력 기능은 아닙니다.
- 자발적 요청, 지원 수준, 행동 빈도·지속시간, 참여시간의 최근 목록은 최대 5건을 보여 줍니다. 전체 집계도 서버에서 불러온 최근 100건과 현재 선택한 학생·활동 필터 안에서 계산합니다.
- 전체 코드를 선택한 값은 여러 학생의 합산입니다. 한 학생의 변화를 보려면 학생 코드를 선택합니다. 코드 미지정 기록을 같은 사람으로 이어 붙이지 않습니다.
- 교사 화면 위쪽 현황은 도움·기분 확인까지 합쳐 최근 100건이므로 오래된 활동은 화면과 ‘이 범위 CSV’ 밖일 수 있습니다. 학기 전체는 아래 ‘학생 성장 보고서’에서 기간을 정해 봅니다.
- 행동 이름이 같아도 정의나 관찰 조건이 바뀌면 직접 비교하기 어렵습니다. ‘자리 이탈’처럼 넓은 이름보다 관찰 기준을 구체적으로 정하고 같은 표현을 사용합니다.
- 장소·상대 역할은 ‘교실·급식실·실습실’, ‘담임교사·다른 교사·친구’처럼 기록합니다. 실제 사람 이름은 적지 않습니다. ‘교실’과 ‘우리 반’이 같은 곳이라면 표현을 통일합니다.

예를 들어 ‘화남 5 → 화남 3’은 보고한 화남의 강도가 낮아진 기록입니다. ‘화남 5 → 편안함 4’는 감정 전환이며 강도 1점 감소로 계산하지 않습니다. ‘편안함 2 → 편안함 4’의 증가를 악화로 판정하지 않습니다. 이 다섯 단계 점수를 비율 척도로 취급하여 ‘40% 개선’이라고 계산하지 않습니다.

## 앱 없이 관찰만 기록하기

앱을 쓰기 어렵거나 그날 앱을 쓰지 않은 학생도 교사 화면의 ‘앱을 쓰지 않은 학생 관찰’에서 학생을 고르고 관찰 항목만 입력해 기록할 수 있습니다(`recordKind: observation`). 학생 감정 응답 칸은 없고, 저장한 시각이 기록일이므로 관찰한 날 바로 기록합니다. 이 기록은 활동 수와 감정 전후 비교에는 들어가지 않고, 생활 속 관찰 지표(2~6)와 성장 보고서에만 들어갑니다.

## 학생 성장 보고서

교사 화면의 ‘학생 성장 보고서’에서 학생과 기간(최근 4주, 최근 8주, 이번 학기, 직접 지정)을 고르면 그 기간의 반 기록을 최근 100건 제한 없이 불러와 한 학생의 변화를 정리합니다. 이번 학기는 3월~8월, 9월~다음 해 2월로 나눕니다.

- **쓰는 기록:** 그 학생으로 확인된 기록만 씁니다. 같은 기간 반 기록 중 학생 미지정 기록 수는 보고서에 따로 적고 넣지 않습니다. ‘선생님이 나중에 지정’한 기록 수도 함께 보여 줍니다.
- **앞 기간과 뒤 기간 비교:** 학생 기록이 실제로 있는 첫날과 마지막 날 사이를 반으로 나눠, 항목마다 횟수와 분모를 나란히 보여 줍니다. 점수 하나로 합친 ‘향상도’는 만들지 않습니다.

| 비교 카드 | 계산 |
|---|---|
| 불편한 감정의 강도가 낮아진 활동 | 속상해요·화가나요·힘들어요를 전후 같은 감정으로 고르고 강도까지 고른 활동 중 강도가 낮아진 횟수 |
| 스스로 요청하기 | 생활 속 관찰의 자발적 요청 수 합 / 요청 기회 수 합 |
| 가장 많았던 표현 지원 | 지원 수준별 관찰 건수 중 가장 많은 것(같으면 함께 표시) |
| 요청 후 필요한 지원을 받음 | 지원 제공 건수 / 결과가 확인된 관찰 건수 |
| 활동 참여시간 | 참여시간 합 / 관찰시간 합 |
| 목표 행동 | 같은 행동 이름별 횟수 합 / 관찰시간 합, 10분당 횟수 |
| 스스로 요청한 장소·상대 | 힌트 없이 1번 이상 요청한 관찰의 장소·상대 역할 종류 수 |

- 카드 아래 문장은 ‘늘었어요·줄었어요·비슷해요’처럼 방향만 말하고 좋아졌다·나빠졌다고 판단하지 않습니다. 어느 한 기간의 분모가 3보다 작으면 ‘기록 수가 적어 우연일 수 있어요’로 표시하고, 분모가 5 이상일 때만 백분율을 덧붙입니다.
- **주별 흐름:** 월요일부터 일요일까지 한 주로 묶습니다. 불편한 감정의 낮아짐·같음·높아짐 막대, 스스로 요청 비율 막대, 주별 표를 보여 줍니다. 기록이 없는 주는 빈칸이나 ‘관찰 없음’으로 두고 0으로 채우지 않습니다.
- **활동별로 보기:** 활동마다 한 횟수와 그중 강도가 낮아진 횟수를 보여 줄 뿐 활동의 효과를 증명하지 않습니다.
- **인쇄·PDF 저장:** 보고서 부분만 인쇄합니다. 별칭과 코드만 들어가므로 실명은 출력한 뒤 직접 적습니다. ‘이 학생 기간 기록 CSV’는 보고서에 쓴 기록을 그대로 내려받습니다.
- 체험 모드에서는 ‘체험용 예시 기록 넣기’로 최근 8주 예시 기록(`appVersion: demo-sample`)을 넣어 화면을 미리 볼 수 있습니다. 실제 학생 기록이 아니며 새로고침하면 사라집니다.

## 감정 미응답이어도 남는 의미

예를 들어 활동 전 화남 4, 활동 후 미응답이고, 실제 수업에서 8번의 요청 기회 중 5번을 힌트 없이 표현했다면 다음처럼 읽습니다.

> 활동 후 감정 변화는 확인하지 못했다. 교사가 관찰한 실제 사용에서는 8번의 기회 중 5번을 스스로 요청했다.

사후 감정을 추정해 채우지 않고 의사소통 관찰을 활용할 수 있습니다. 같은 조건에서 이런 변화가 반복되고 필요한 힌트가 줄며 실제 지원이 이어지는지 확인합니다. 반대로 활동 종료나 칭찬 화면 도달만으로 정서 안정·기능 향상·생활 속 일반화를 확정하지 않습니다. 이 화면은 기술적 집계이며 통계적 유의성 검정이나 앱 단독 효과 입증 기능은 아닙니다.

## 저장·내보내기 범위

교사 화면의 ‘이 범위 CSV 저장’은 현재 불러온 기록 중 선택한 필터 범위를 저장합니다. 학생 전후 자기보고, 미응답 이유, 연습 내용, 교사 관찰, 상태·코드, 생성·관찰 수정 이력을 서로 다른 열로 담습니다. 빈 수치는 공란으로 남으며 0은 실제 0으로 표시합니다. 스프레드시트가 입력 문장을 수식으로 실행하지 않도록 내보내기 값을 처리합니다.

현재 교사 관찰과 과거 기록의 코드 수정은 Firestore에만 반영됩니다. 기존 Google Sheets 행을 자동 갱신하지 않습니다. 체험 모드에서는 이마저 외부 저장 없이 메모리에만 남습니다. 기존 Apps Script 원본과 운영 주소를 확인하고 신뢰할 수 있는 서버 연동을 구현해야 두 저장소가 같은 최신 결과를 유지할 수 있습니다.

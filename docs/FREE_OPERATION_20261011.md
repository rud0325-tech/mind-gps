# 마음GPS 학생 지정·무료 알림 운영 안내

작성일: 2026-10-11. 이 문서는 이번 수정본의 기록·알림 구조를 설명합니다. 코드 저장과 실제 서버 배포는 서로 다른 단계입니다. 학교 운영 주소에 운영 버전 `2026-10-11-free-safety-v3`을 배포해 검증했습니다. 공개판에는 운영 주소와 배포 기록을 싣지 않습니다.

## 교사와 학생이 사용하는 순서

1. 운영자가 승인한 교사가 Google 계정으로 로그인합니다. Google 로그인만 했다고 교사 기록에 접근할 수 있는 것은 아닙니다.
2. 교사가 반과 학생 별칭을 등록합니다. S01 같은 코드는 기록을 연결하는 내부 표식이며, 학생이 입력하거나 외울 필요가 없습니다.
3. 공용 태블릿의 브라우저마다 교사가 한 번 로그인해 ‘교실 공용 기기’로 등록합니다. 등록 후에는 교사 화면에서 나가고, 학생용 브라우저에 Google 계정 로그인을 남기지 않습니다.
4. 교사가 자신의 PC에서 태블릿별 학생을 고르고 수업을 시작합니다. 학생 지정은 수업 동안 유지됩니다. 설정한 수업 시간이 지나거나 수업 종료를 누르면 해제됩니다.
5. 태블릿을 다른 학생에게 넘길 때 교사가 새 학생을 고르고 ‘이 기기 학생 변경’을 누릅니다. 진행 중이던 화면은 처음 화면으로 돌아갑니다. 중단 기록은 활동을 시작한 이전 학생에게 남습니다.
6. 학생은 계정 입력 없이 화면을 터치하고 캐릭터를 고릅니다. 캐릭터는 학생을 구별하는 ID가 아닙니다.

‘기기’는 기계의 일련번호가 아니라 **이 브라우저의 익명 로그인**입니다. 다른 브라우저를 쓰거나 사이트 데이터를 지우면 다시 등록해야 합니다. 전용 기기는 한 학생을 고정하고, 공용 기기는 수업마다 또는 학생이 바뀔 때 지정합니다. 미지정 학생 기록을 임의로 같은 학생의 성장 기록으로 묶지 않습니다.

## 저장과 보안

- 활동 시작 때 서버가 확인한 반·학생 코드·수업 시작 교사·지정 번호를 `learningSessions`에 고정합니다. 학생 변경 이후 들어오는 이전 기록에도 그때의 식별을 적용합니다.
- 학생 기록 원본은 Firestore `activityRecords`에 저장합니다. 교사는 담당 반만 조회하고, 학생은 다른 학생의 활동 기록을 조회할 수 없습니다.
- 승인 교사 문서에는 `approved: true`가 명시돼야 합니다. 이번 적용 전에는 기존 승인 교사 문서의 이 항목을 확인해야 합니다.
- 교사 알림 주소는 Google이 확인한 로그인 이메일과 일치해야 합니다. 학생 화면에서 받는 사람 주소를 전달하거나 바꾸지 않습니다.
- 새 Apps Script는 Firebase 로그인 토큰과 기록 번호만 받습니다. 서버가 실제 기록과 교사 권한을 다시 확인하고 내용을 만듭니다. 브라우저에는 관리자 비밀번호·서비스 계정 비밀 키를 넣지 않습니다.
- 교사 로그인은 학생의 익명 로그인과 분리됩니다. 공용 기기에 남아 있는 Google 웹 로그인 자체를 앱이 대신 지울 수는 없습니다.

**이번 새 알림 경로는 Google Sheets에 행을 추가하지 않습니다.** Firestore가 원본이며, 교사 화면의 CSV 내보내기는 유지합니다. 이전 공개 Apps Script에 원자료를 전송하던 경로는 사용하지 않습니다. Sheets 자동 동기화가 필요하면 인증·중복·수정 이력까지 처리하는 별도 연결을 정해야 합니다.

## 긴급 이메일

부정 감정(속상해요·화가나요·힘들어요) 강도 5를 누르거나 도움 요청 버튼을 누르면, 기록과 발송 대기 항목을 함께 저장한 뒤 즉시 발송을 요청합니다. 강도 5는 ‘다음’을 기다리지 않습니다. 캐릭터를 고르기 전 도움 요청도 지원합니다. 기분 좋음·편안함 강도 5는 긴급 알림 조건이 아닙니다.

수신자는 **그 수업을 시작한 교사의 Google 로그인 이메일**입니다. 수업이 없는 등록 기기의 도움 요청은 해당 기기를 등록한 교사에게 연결됩니다. 미등록 기기는 받는 교사를 확정할 수 없어 학생에게 가까운 교사에게 직접 알리도록 안내합니다.

실패한 즉시 요청은 약 1분 간격의 서버 작업이 확인합니다. 메일 시스템과 네트워크 사정에 따라 지연될 수 있으며, 메일함 도착 시간·열람까지 보장하지 않습니다.

| 교사 화면 상태 | 의미와 다음 행동 |
|---|---|
| 발송 대기 | 요청이 저장됐고 서버 처리를 기다림. 오래 지속되면 서버 연결·실행 확인 |
| 발송 처리 중 | 발송 전에 처리 중 상태를 먼저 저장함 |
| 발송 요청 성공 | Google 메일 발송 함수가 성공했음. 수신함 도착·읽음 확인과는 다름 |
| 발송 실패 | 교사 승인·주소 같은 발송 전 오류. 제한된 자동 재시도 후 수동 확인 |
| 무료 발송 한도 부족 | 잔여 한도 없음 또는 하루 보호 한도. 유료 전환 없이 대기 |
| 발송 결과 확인 필요 | 발송 중 연결 중단 등으로 실제 발송 여부를 모름. 메일함을 확인하고 중복 가능성을 확인한 뒤 재시도 |

학생 지원 확인과 메일 상태는 별개입니다. 교사가 지원을 확인해도 실패 메일은 목록에서 숨기지 않습니다. **지원 확인 + 발송 요청 성공**이 함께 충족돼야 열린 알림 목록에서 빠집니다. 실패 내역은 일반 기록 최근 100건과 독립된 목록에서 오래된 것부터 확인하며, 100건씩 다음 페이지를 볼 수 있습니다.

같은 사건의 재시도나 강도 5 이후 활동 완료 기록으로 같은 단계 알림이 반복 발송되지 않게 처리합니다. 학생이 도움 버튼을 새로 누른 사건은 별도 요청입니다. 전후 감정 강도 5도 각각 확인합니다.

## 무료 운영 범위

이번에 확인한 운영 대상 Firebase 프로젝트는 결제 연결이 꺼져 있고 Firestore 지역은 서울(`asia-northeast3`)입니다. 다른 과거 프로젝트의 결제 상태와는 별개입니다. 결제 계정을 새로 연결하거나 유료 서버를 추가하지 않습니다.

- Firestore 무료 할당량과 Firebase Hosting 무료 전송량 안에서 운영합니다. 사용량 초과 시 자동 유료 전환 대신 저장·접속이 제한될 수 있습니다.
- 일반 Gmail 계정의 Apps Script 발송 한도는 하루 수신자 100명입니다. 같은 Google 계정의 다른 스크립트 사용량도 함께 영향을 줍니다. 앱은 현재 잔여 한도를 확인하고, 별도로 하루 90명 보호 한도를 적용합니다. **교사별 90명이 아니라 이 스크립트 발송 계정 전체의 한도**입니다.
- 앱 보호 한도는 서울 날짜 기준이며, Google의 할당량 회복 시점과 다를 수 있습니다. 실제 남은 Google 한도가 우선입니다.
- 메일 한도뿐 아니라 Apps Script 실행 시간·Firestore 읽기/쓰기·Hosting 전송 한도도 영향을 줍니다. 서버 실행 상태와 확인 당시 메일 잔여 한도를 교사 화면에 표시합니다.
- 무료라는 이유로 무제한 운영이나 24시간 알림 수신이 보장되지는 않습니다. 한도·연결 실패가 표시되면 교사가 학생 상태를 직접 확인해야 합니다.

공식 기준: [Apps Script 할당량](https://developers.google.com/apps-script/guides/services/quotas), [Firestore 무료 할당량](https://firebase.google.com/docs/firestore/quotas), [Hosting 사용량](https://firebase.google.com/docs/hosting/usage-quotas-pricing).

## 배포 순서

1. 기존 Hosting 릴리스와 Firestore 규칙·교사 승인 문서를 보관합니다.
2. `services/apps-script/Code.gs`와 `appsscript.json`을 새 스크립트에 저장합니다. 프로젝트 ID와 웹 API 키를 스크립트 속성(`FIREBASE_PROJECT_ID`, `FIREBASE_WEB_API_KEY`)에 넣습니다. 알림 메일에 앱 주소를 넣으려면 `APP_URL` 속성도 추가합니다. 이 공개 Firebase 웹 API 키는 관리자 비밀 키가 아닙니다.
3. Google 기록 확인·메일 발송·재시도 트리거 권한을 승인합니다. 웹앱은 소유자로 실행합니다. 접근 가능한 웹 주소여도 Firebase 토큰·서버 기록 검사를 통과한 요청만 처리합니다.
4. 새 웹앱 주소를 `VITE_GOOGLE_SCRIPT_URL`에 설정합니다. 기존 승인 교사의 `approved: true`를 확인하고 새 규칙·색인을 준비합니다.
5. 실제 학생 정보가 없는 별도 시험 반에서 도움 요청과 부정 감정 5 알림 각 1건을 검증합니다. 발송 결과와 수신을 구분해 확인합니다.
6. 실제 모드·에뮬레이터 꺼짐으로 빌드하고 Hosting을 적용합니다. `scripts/check-live-release.mjs`가 체험/가상 서버/메일 주소 누락 빌드의 실수 배포를 차단합니다. 이 설정 검사는 실제 발송 시험을 대신하지 않습니다.
7. `installRecoveryTrigger`를 한 번 실행해 재시도 작업을 설치합니다. 실제 실행과 `mailServiceHealth/current` 갱신을 확인합니다.
8. 새 연결이 검증된 뒤, 이전 공개 알림 스크립트를 계속 사용할지 결정합니다. 이전 공개 발송 주소가 살아 있으면 새 코드와 별개로 메일 한도를 소모할 위험이 남습니다. 사용자가 2026-10-11에 이전 공개 배포 중단을 승인했습니다. 코드와 시트 기록은 유지하고 배포만 보관 처리합니다.

보존 기간·자동 삭제·App Check 등 추가 운영 정책은 아직 확정하거나 구현하지 않았습니다. 기록이 많아지면 보관량을 점검해야 합니다. 이 문서나 자동 테스트 통과가 모든 보안 위험의 제거를 뜻하지는 않습니다.

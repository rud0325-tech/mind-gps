# 사회정서학습 앱 UDL·웹 접근성 검토 체크리스트

Oct 7, 2026 · @윤경

## 사용 방법

모든 항목은 공식 문서의 기준 문장에서 가져왔고, 항목마다 근거 번호를 붙였습니다. 공식 문서에 없는 숫자(터치 횟수, 활동 시간, 선택지 개수 등)는 넣지 않았습니다.

**근거 문서와 구속력**

| 근거 | 성격 | 판정 방식 |
| --- | --- | --- |
| [KWCAG 2.2 (KS X OT0003:2022)](https://a11ykr.github.io/kwcag22/) | 국가 표준. 「지능정보화기본법」, 「장애인차별금지법」에 따른 웹 접근성 의무의 기준 | 충족 / 미충족 / 해당 없음 |
| WCAG 2.1·2.2 AA 성공기준 (KWCAG 부속서 A 및 W3C) | 국제 표준. KWCAG에 없는 AA 기준을 보완 | 충족 / 미충족 / 해당 없음 |
| CAST UDL Guidelines 3.0 | 설계 지침. CAST는 고려사항을 체크리스트가 아닌 질문 목록이라고 밝힘 | 반영함 / 장벽 남음 |
| W3C COGA (인지·학습장애 사용성) | 권고 성격의 그룹 노트. 법적 의무 아님 | 반영함 / 장벽 남음 |
| [교육부 학습지원 소프트웨어 선정기준 (2025.12.30)](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=294&boardSeq=105007&lev=0&m=020) | 「초·중등교육법」 제29조의2에 따른 필수기준 | 충족 / 미충족 |

**판정 원칙**

- 한 화면이라도 기준을 어기면 미충족입니다. 글, 그림+단어, 그림 모드와 실제 사용하는 기기마다 따로 확인합니다.
- 증거(측정값, 화면 캡처, 검사 도구 결과)를 남긴 항목만 충족으로 봅니다.
- KWCAG 2.2는 "단일 장애를 지닌 사용자에게 필요한 대부분의 접근성 문제"를 다루며, 중복장애 사용자는 표준만으로 접근이 어려울 수 있다고 스스로 밝힙니다. 그래서 KWCAG를 모두 충족해도 학생 관찰은 따로 필요합니다.

**이 체크리스트가 다루지 않는 것**

- 사회정서학습 내용의 타당성(기법을 원래 이론대로 옮겼는지)은 표준으로 판정할 수 없어, 특수교육·상담 전문가의 내용 검토로 따로 확인합니다.
- 활동 길이, 선택지 개수 같은 숫자 기준은 공식 기준이 없으므로, 필요하면 학생 관찰 결과로 학급 자체 기준을 정하고 그 사실을 밝혀 둡니다.

## 웹 접근성 ① 인식의 용이성

KWCAG 2.2의 인식의 용이성 9개 검사항목과, KWCAG에 없는 WCAG 2.1 AA 기준 6개입니다. 각 항목의 굵은 글씨는 표준 문장, 그 뒤는 앱에서 확인할 곳입니다.

**KWCAG 2.2 검사항목**

- [ ] **5.1.1 적절한 대체 텍스트 제공:** 텍스트 아닌 콘텐츠는 그 의미나 용도를 인식할 수 있도록 대체 텍스트를 제공해야 한다. 캐릭터, 감정 상징, 아이콘 버튼마다 확인하고, 꾸밈용 그림은 공백 대체 텍스트로 처리했는지 봅니다.
- [ ] **5.2.1 자막 제공:** 멀티미디어 콘텐츠에는 자막, 대본 또는 수어를 제공해야 한다. 안내 음성과 영상이 대상이며, 표준은 음성만 제공하는 경우에도 자막, 대본 또는 수어를 요구합니다.
- [ ] **5.3.1 표의 구성:** 표는 이해하기 쉽게 구성해야 한다. 교사 화면의 기록 표에 제목 셀과 데이터 셀이 구분되어 있는지 봅니다.
- [ ] **5.3.2 콘텐츠의 선형구조:** 콘텐츠는 논리적인 순서로 제공해야 한다. 화면낭독기가 읽는 순서가 화면 흐름과 같은지 봅니다.
- [ ] **5.3.3 명확한 지시사항 제공:** 지시사항은 모양, 크기, 위치, 방향, 색, 소리 등에 관계없이 인식될 수 있어야 한다. "오른쪽 버튼", "초록 카드"처럼 위치나 색만으로 가리키는 안내가 없는지 봅니다.
- [ ] **5.4.1 색에 무관한 콘텐츠 인식:** 콘텐츠는 색에 관계없이 인식될 수 있어야 한다. 감정 강도, 선택 상태, 캐릭터를 흑백 화면에서도 구분할 수 있는지 봅니다.
- [ ] **5.4.2 자동 재생 금지:** 자동으로 소리가 재생되지 않아야 한다. 3초 미만의 소리는 허용되며, 3초 이상 재생되는 소리에는 멈춤, 일시정지, 음량 조절 수단이 있어야 합니다.
- [ ] **5.4.3 텍스트 콘텐츠의 명도 대비:** 텍스트 콘텐츠와 배경 간의 명도 대비는 4.5 대 1 이상이어야 한다. 18pt 이상 또는 14pt 굵은 글자는 3 대 1까지 허용됩니다. 캐릭터 색 얼굴창 위의 글자도 측정합니다.
- [ ] **5.4.4 콘텐츠 간의 구분:** 이웃한 콘텐츠는 구별될 수 있어야 한다. 카드와 버튼 사이가 테두리, 구분선, 간격 등으로 구분되는지 봅니다.

**WCAG 2.1 AA 보완 기준**

- [ ] **1.3.4 방향 (AA):** 화면을 가로나 세로 한 방향으로만 제한하지 않는다.
- [ ] **1.4.4 텍스트 크기 조정 (AA):** 콘텐츠와 기능의 손실 없이 글자를 200%까지 확대할 수 있다.
- [ ] **1.4.10 리플로우 (AA):** 400%로 확대해도 가로와 세로 스크롤이 동시에 생기지 않는다.
- [ ] **1.4.11 텍스트가 아닌 콘텐츠의 명도 대비 (AA):** 버튼, 입력 칸 같은 인터페이스와 내용 이해에 필요한 그래픽은 3:1 이상의 대비를 갖는다.
- [ ] **1.4.12 글자 간격 (AA):** 줄 간격 1.5배, 문단 간격 2배, 글자 간격 0.12배, 단어 간격 0.16배로 바꿔도 내용과 기능이 유지된다.
- [ ] **1.4.13 호버 또는 초점을 받은 콘텐츠 (AA):** 마우스 오버나 초점으로 나타난 콘텐츠는 닫을 수 있고, 유지되는 동안 사라지지 않는다.

출처: [KWCAG 2.2 온라인판 (부속서 A 포함)](https://a11ykr.github.io/kwcag22/)

## 웹 접근성 ② 운용의 용이성

KWCAG 2.2의 운용의 용이성 15개 검사항목과, WCAG 2.1·2.2의 AA 보완 기준입니다. AAA 기준은 의무가 아니지만 인지·발달장애 학생과 관련이 커서 '선택'으로 따로 적었습니다.

**KWCAG 2.2 검사항목**

- [ ] **6.1.1 키보드 사용 보장:** 모든 기능은 키보드만으로도 사용할 수 있어야 한다. 표준은 키보드 조작 횟수의 많고 적음은 고려 대상이 아니라고 밝힙니다.
- [ ] **6.1.2 초점 이동과 표시:** 키보드에 의한 초점은 논리적으로 이동해야 하며, 시각적으로 구별할 수 있어야 한다. 초점이 빠져나오지 못하는 곳(함정)이 없어야 합니다.
- [ ] **6.1.3 조작 가능:** 사용자 입력 및 콘트롤은 조작 가능하도록 제공되어야 한다. 표준은 모든 콘트롤의 대각선 길이를 6.0mm 이상으로 제공하는 것이 바람직하다고 제시합니다.
- [ ] **6.1.4 문자 단축키:** 문자 단축키는 오동작으로 인한 오류를 방지하여야 한다. (단축키가 없으면 해당 없음)
- [ ] **6.2.1 응답시간 조절:** 시간제한이 있는 콘텐츠는 응답시간을 조절할 수 있어야 한다. 시간이 지나면 넘어가는 화면, 자동 로그아웃이 대상입니다.
- [ ] **6.2.2 정지 기능 제공:** 자동으로 변경되는 콘텐츠는 움직임을 제어할 수 있어야 한다. 움직이는 캐릭터, 자동으로 넘어가는 안내가 대상입니다.
- [ ] **6.3.1 깜빡임과 번쩍임 사용 제한:** 초당 3\~50회 주기로 깜빡이거나 번쩍이는 콘텐츠를 제공하지 않아야 한다. 표준은 10인치 이상 화면에서 특히 주의하라고 밝혀, 전자칠판과 태블릿 사용 시 중요합니다.
- [ ] **6.4.1 반복 영역 건너뛰기:** 콘텐츠의 반복되는 영역은 건너뛸 수 있어야 한다. (반복 메뉴가 없으면 해당 없음)
- [ ] **6.4.2 제목 제공:** 페이지, 프레임, 콘텐츠 블록에는 적절한 제목을 제공해야 한다. 한 페이지 앱이라도 화면이 바뀔 때 제목이 바뀌는지 봅니다.
- [ ] **6.4.3 적절한 링크 텍스트:** 링크 텍스트는 용도나 목적을 이해할 수 있도록 제공해야 한다. 집 모양처럼 아이콘만 있는 버튼은 그 의미가 직관적이고 대체 텍스트가 있어야 합니다.
- [ ] **6.4.4 고정된 참조 위치 정보:** 전자출판문서 형식의 웹 페이지에 적용된다. (해당 없음이 일반적)
- [ ] **6.5.1 단일 포인터 입력 지원:** 다중 포인터 또는 경로기반 동작을 통한 입력은 단일 포인터 입력으로도 조작할 수 있어야 한다. 끌어 놓기, 두 손가락 확대가 대상입니다.
- [ ] **6.5.2 포인터 입력 취소:** 단일 포인터 입력으로 실행되는 기능은 취소할 수 있어야 한다. 누르는 순간이 아니라 떼는 순간 실행되는지 봅니다.
- [ ] **6.5.3 레이블과 네임:** 화면에 보이는 버튼 글자가 화면낭독기 이름에 포함되어야 한다.
- [ ] **6.5.4 동작기반 작동:** 기기를 흔들거나 기울여 작동하는 기능은 버튼으로도 조작할 수 있고 끌 수 있어야 한다. (없으면 해당 없음)

**WCAG 2.1·2.2 AA 보완 기준**

- [ ] **2.4.6 제목과 레이블 (AA, 2.1):** 화면 제목과 버튼 이름이 내용을 적절히 설명한다.
- [ ] **2.4.11 초점이 가려지지 않음 (AA, 2.2):** 초점을 받은 요소가 다른 콘텐츠에 완전히 가려지지 않는다.
- [ ] **2.5.7 끌기 동작 (AA, 2.2):** 끌기로 하는 모든 기능을 끌기 없이 한 번 누르기로도 할 수 있다.
- [ ] **2.5.8 타겟 크기 최소 (AA, 2.2):** 누르는 대상은 24×24 CSS 픽셀 이상이거나, 이웃한 대상과 충분한 간격이 있다.

**선택 기준 (AAA)**

- [ ] **2.2.3 시간 제한 없음:** 필수적이지 않으면 시간 제한을 두지 않는다.
- [ ] **2.2.4 인터럽트:** 긴급 상황이 아니면 갱신이나 알림을 미루거나 끌 수 있다.
- [ ] **2.3.3 상호작용 애니메이션:** 꼭 필요하지 않은 상호작용 애니메이션을 끌 수 있다.
- [ ] **2.5.5 타겟 크기 (향상):** 누르는 대상이 44×44 CSS 픽셀 이상이다.

## 웹 접근성 ③ 이해의 용이성

KWCAG 2.2의 이해의 용이성 7개 검사항목과 WCAG 2.1·2.2 보완 기준입니다. 읽기 수준 관련 기준(3.1.5)은 AAA지만 지적장애 학생과 직접 관련되어 선택 기준으로 넣었습니다.

**KWCAG 2.2 검사항목**

- [ ] **7.1.1 기본 언어 표시:** 주로 사용하는 언어를 명시해야 한다. 앱 문서에 한국어(lang="ko")가 지정되어 있는지 봅니다.
- [ ] **7.2.1 사용자 요구에 따른 실행:** 사용자가 의도하지 않은 기능(새 창, 초점에 의한 맥락 변화 등)은 실행되지 않아야 한다. 표준은 선택 항목을 고르는 것만으로 기능이 실행되지 않고, 함께 제공되는 실행 버튼을 눌렀을 때 실행되어야 한다고 설명합니다. 카드를 고르자마자 다음 화면으로 넘어가는 곳을 모두 확인합니다.
- [ ] **7.2.2 찾기 쉬운 도움 정보:** 도움 정보가 제공되는 경우, 각 페이지에서 동일한 상대적인 순서로 접근할 수 있어야 한다. 도움 요청 버튼, 사용 방법 안내가 대상입니다.
- [ ] **7.3.1 오류 정정:** 입력 오류를 정정할 수 있는 방법을 제공해야 한다. 오류가 난 위치와 이유를 알려 주는지 봅니다.
- [ ] **7.3.2 레이블 제공:** 사용자 입력에는 대응하는 레이블을 제공해야 한다. 선택 카드와 입력 칸이 화면낭독기에 이름으로 읽히는지 봅니다.
- [ ] **7.3.3 접근 가능한 인증:** 인증 과정은 인지 기능 테스트에만 의존해서는 안 된다. 표준은 비밀번호 입력도 인지 기능 테스트의 예로 들며, OAuth 등 다른 방법을 하나 이상 제공하라고 합니다. 교사 PIN만으로 들어가는 구조라면 미충족입니다.
- [ ] **7.3.4 반복 입력 정보:** 반복되는 입력 정보는 자동 입력 또는 선택 입력할 수 있어야 한다. 한 활동 안에서 앞서 고른 캐릭터나 모드를 다시 고르게 하지 않는지 봅니다.

**WCAG 2.1·2.2 보완 기준**

- [ ] **3.1.2 특정 부분의 언어 (AA, 2.1):** 다른 언어로 된 부분은 그 언어를 명시한다.
- [ ] **3.2.3 일관된 내비게이션 (AA, 2.1):** 처음으로, 이전으로 같은 이동 버튼이 화면마다 같은 순서로 나온다.
- [ ] **3.2.4 일관된 식별 (AA, 2.1):** 같은 기능의 아이콘과 버튼은 같은 형태와 이름을 쓴다.
- [ ] **3.3.3 오류 제안 (AA, 2.1):** 입력 오류가 있으면 올바른 입력 방법을 제안한다.
- [ ] **3.3.8 접근 가능한 인증 최소 (AA, 2.2):** 인증 과정에서 기억이나 퍼즐 같은 인지 기능 테스트를 요구하지 않거나 대안을 제공한다.

**선택 기준 (AAA)**

- [ ] **3.1.3 생소한 단어:** 어려운 용어와 전문용어에 설명을 제공한다. ('증거', 'REBT' 같은 말)
- [ ] **3.1.5 읽기 수준:** 중학교 교육 수준을 넘는 읽기 능력이 필요한 내용에는 예시, 이미지 같은 보조 자료나 쉬운 버전을 함께 제공한다.
- [ ] **3.3.5 도움:** 상황에 맞는 도움말을 제공한다.
- [ ] **3.3.6 오류 방지 (모든 경우):** 데이터를 바꾸거나 보내는 모든 경우, 되돌리기나 최종 확인 기능 중 하나 이상을 제공한다. 도움 요청 전송이 대상입니다.

## 웹 접근성 ④ 견고성

KWCAG 2.2의 견고성 2개 검사항목과 WCAG 2.1 보완 기준입니다. 국내 기준인 KWCAG 2.2에는 8.1.1이 그대로 있으므로, WCAG 2.2에서 하나의 기준이 삭제된 것과 관계없이 점검합니다.

**KWCAG 2.2 검사항목**

- [ ] **8.1.1 마크업 오류 방지:** 마크업 언어의 요소는 열고 닫음, 중첩 관계 및 속성 선언에 오류가 없어야 한다. 같은 id 값이 한 문서에 두 번 쓰이지 않는지도 봅니다. (마크업 검사 도구 결과 저장)
- [ ] **8.2.1 웹 애플리케이션 접근성 준수:** 콘텐츠에 포함된 웹 애플리케이션은 접근성이 있어야 한다. 표준은 새로 만든 기능의 명칭, 역할, 상태, 값을 보조기술이 알 수 있게 전달하라고 요구합니다. div로 만든 카드 버튼, 소리 재생 버튼, 선택 상태가 대상입니다.

**WCAG 2.1 보완 기준**

- [ ] **4.1.2 이름, 역할, 값 (A):** 직접 만든 인터페이스에 이름, 역할, 값, 상태 정보를 제공한다. (KWCAG 8.2.1과 같은 방향의 국제 기준)
- [ ] **4.1.3 상태 메시지 (AA):** "저장했어요", "선생님께 알렸어요" 같은 상태 메시지를 초점 이동 없이도 화면낭독기가 읽는다.

**보조기술 실사용 확인**

표준의 8.2.1은 국내 보조기술로 접근이 불가능한 웹 애플리케이션은 가능한 한 사용하지 않는 것이 좋다고 밝힙니다. 그래서 아래 확인 결과를 8.2.1의 증거로 남깁니다.

- [ ] 학교에서 실제로 쓰는 기기의 화면낭독기(iPad VoiceOver, 안드로이드 TalkBack 등)로 모든 활동을 끝까지 할 수 있다.
- [ ] 기기의 확대, 고대비, 굵은 글씨 설정을 켜도 기능이 유지된다.

출처: [KWCAG 2.2 온라인판 (부속서 A 포함)](https://a11ykr.github.io/kwcag22/)

## UDL 3.0 참여의 다양한 수단

CAST UDL 3.0의 참여 원칙(지침 7\~9) 고려사항 13개입니다. 굵은 글씨가 CAST의 고려사항 이름이고, 그 뒤는 이 앱에 적용해 던지는 질문입니다. 판정은 '반영함' 또는 '장벽 남음'으로 하고, 장벽이 남으면 어떤 학생에게 어떤 장벽인지 적습니다.

**지침 7. 흥미와 정체성 반기기**

- [ ] **7.1 선택과 자율성 최적화 (Optimize choice and autonomy):** 학생이 캐릭터, 활동, 표현 방식을 스스로 고를 수 있는가?
- [ ] **7.2 관련성, 가치, 진정성 최적화 (Optimize relevance, value, and authenticity):** 상황과 예시가 학생의 실제 생활에서 나왔는가?
- [ ] **7.3 즐거움과 놀이 기르기 (Nurture joy and play):** 활동에 학생이 즐겁게 느끼는 요소가 있는가?
- [ ] **7.4 편견, 위협, 방해 요소 다루기 (Address biases, threats, and distractions):** 비교, 실패 표시, 갑작스러운 자극처럼 위협이나 방해가 되는 요소가 없는가? 캐릭터와 예시에 고정관념이 없는가?

**지침 8. 노력과 지속 돕기**

- [ ] **8.1 목표의 의미와 목적 명확히 하기 (Clarify the meaning and purpose of goals):** 각 활동이 무엇을 위한 것인지 학생이 알 수 있는가?
- [ ] **8.2 도전과 지원 최적화 (Optimize challenge and support):** 글, 그림+단어, 그림 모드처럼 수준에 맞는 지원을 고를 수 있는가?
- [ ] **8.3 협력, 상호의존, 공동 학습 촉진 (Foster collaboration, interdependence, and collective learning):** 앱에서 배운 것을 친구나 교사와 함께 나누는 활동으로 이어지는가?
- [ ] **8.4 소속감과 공동체 형성 (Foster belonging and community):** 학생이 자신이 받아들여진다고 느끼게 하는가? (말투, 캐릭터 다양성)
- [ ] **8.5 행동 지향적 피드백 제공 (Offer action-oriented feedback):** 피드백이 다음에 할 행동을 알려 주는가?

**지침 9. 정서 역량**

- [ ] **9.1 기대, 신념, 동기 인식하기 (Recognize expectations, beliefs, and motivations):** 학생이 "나는 못 해" 같은 생각을 알아차리고 다르게 볼 기회가 있는가?
- [ ] **9.2 자신과 타인에 대한 인식 기르기 (Develop awareness of self and others):** 자기 감정과 강도를 알아차리고, 상대의 입장도 생각해 보는 단계가 있는가?
- [ ] **9.3 개인적·공동의 성찰 촉진 (Promote individual and collective reflection):** 활동 전후를 비교하거나 돌아볼 기회가 있는가?
- [ ] **9.4 공감과 회복적 실천 기르기 (Cultivate empathy and restorative practices):** 갈등 상황에서 관계를 회복하는 방법(나 전달법 등)을 연습하는가?

## UDL 3.0 표상의 다양한 수단

CAST UDL 3.0의 표상 원칙(지침 1\~3) 고려사항 12개입니다.

**지침 1. 지각**

- [ ] **1.1 정보 표시 방식을 조정할 기회 지원 (Support opportunities to customize the display of information):** 글자 크기, 글꼴, 간격, 배경색 등을 학생에 맞게 바꿀 수 있는가? CAST는 3.0 개정에서 이 고려사항에 글꼴, 글자 크기, 글자·줄 간격, 배경색, 글자색 조정을 구체적으로 넣었습니다.
- [ ] **1.2 정보를 지각하는 여러 방법 지원 (Support multiple ways to perceive information):** 같은 내용을 글, 그림, 소리로 모두 받을 수 있는가?
- [ ] **1.3 다양한 관점과 정체성을 진정성 있게 표현 (Represent a diversity of perspectives and identities in authentic ways):** 캐릭터와 상황에 여러 관점과 정체성이 담겨 있는가?

**지침 2. 언어와 기호**

- [ ] **2.1 어휘, 기호, 언어 구조 명확히 하기 (Clarify vocabulary, symbols, and language structures):** 어려운 말과 상징의 뜻을 쉽게 풀어 주는가? 같은 대상을 같은 말로 부르는가?
- [ ] **2.2 글자, 수식, 기호의 해독 지원 (Support decoding of text, mathematical notation, and symbols):** 글을 읽기 어려운 학생에게 소리로 듣기가 있는가? 감정 강도 숫자를 그림으로도 보여 주는가?
- [ ] **2.3 언어와 방언 간의 이해와 존중 기르기 (Cultivate understanding and respect across languages and dialects):** 한국어가 모국어가 아닌 학생을 위한 대안이 있는가?
- [ ] **2.4 언어와 기호 사용의 편견 다루기 (Address biases in the use of language and symbols):** 문장과 상징에 장애, 성별, 가정 형태에 대한 편견이 없는가?
- [ ] **2.5 여러 매체로 보여 주기 (Illustrate through multiple media):** 그림, 소리, 캐릭터 시범 등 여러 매체로 개념을 보여 주는가?

**지침 3. 지식 구축**

- [ ] **3.1 이전 지식과 새 학습 연결 (Connect prior knowledge to new learning):** 학생이 이미 아는 경험과 연결해 주는가?
- [ ] **3.2 패턴, 핵심 특징, 큰 개념, 관계 강조 (Highlight and explore patterns, critical features, big ideas, and relationships):** 활동마다 같은 단계 틀을 써서 핵심 구조가 드러나는가?
- [ ] **3.3 여러 방식의 앎과 의미 만들기 (Cultivate multiple ways of knowing and making meaning):** 학생이 자기 방식으로 감정과 상황을 이해할 여지가 있는가?
- [ ] **3.4 전이와 일반화 극대화 (Maximize transfer and generalization):** 앱에서 배운 것을 교실, 실습, 가정 등 실제 상황에서 쓰도록 이어 주는가?

## UDL 3.0 행동과 표현의 다양한 수단

CAST UDL 3.0의 행동과 표현 원칙(지침 4\~6) 고려사항 11개입니다.

**지침 4. 상호작용**

- [ ] **4.1 반응, 탐색, 움직임 방법을 다양화하고 존중 (Vary and honor the methods for response, navigation, and movement):** 터치, 키보드, 스위치 등 여러 방법으로 조작하고 답할 수 있는가?
- [ ] **4.2 접근 가능한 자료와 보조기술 이용 최적화 (Optimize access to accessible materials and assistive and accessible technologies and tools):** 화면낭독기, 확대, 스위치 같은 보조기술과 함께 쓸 수 있는가? (웹 접근성 ①\~④ 결과로 판단)

**지침 5. 표현과 의사소통**

- [ ] **5.1 의사소통에 여러 매체 사용 (Use multiple media for communication):** 학생이 글, 그림, 소리 중 편한 방식으로 감정과 생각을 표현할 수 있는가?
- [ ] **5.2 구성, 작성, 창작에 여러 도구 사용 (Use multiple tools for construction, composition, and creativity):** 문장을 만들 때 카드 고르기, 듣기 등 여러 도구를 쓸 수 있는가?
- [ ] **5.3 단계적 지원으로 연습과 수행의 유창성 기르기 (Build fluencies with graduated support for practice and performance):** 처음엔 많이 돕고 익숙해지면 지원을 줄이는 구조가 있는가?
- [ ] **5.4 표현과 의사소통 방식에 관한 편견 다루기 (Address biases related to modes of expression and communication):** 말을 하지 않거나 그림으로만 표현하는 학생의 방식도 똑같이 인정하는가?

**지침 6. 전략 개발**

- [ ] **6.1 의미 있는 목표 세우기 (Set meaningful goals):** 학생이 자신에게 필요한 목표(예: 화날 때 말로 표현하기)를 알 수 있는가?
- [ ] **6.2 어려움을 예상하고 계획하기 (Anticipate and plan for challenges):** 방법이 통하지 않을 때의 대안을 미리 연습하는가?
- [ ] **6.3 정보와 자원 정리하기 (Organize information and resources):** 단계와 선택지가 정리된 순서로 제시되는가?
- [ ] **6.4 진행 상황을 점검하는 역량 강화 (Enhance capacity for monitoring progress):** 학생이 지금 몇 단계인지, 활동 전후 마음이 어떻게 달라졌는지 볼 수 있는가?
- [ ] **6.5 배제적 관행에 도전하기 (Challenge exclusionary practices):** 특정 학생이 쓸 수 없게 만드는 설계(글만 있는 화면, 색으로만 구분 등)가 남아 있지 않은가?

## 인지·학습장애 접근성 (W3C COGA)

W3C의 「Making Content Usable for People with Cognitive and Learning Disabilities」는 WCAG 요구사항을 넘어서는 보충 지침으로, 8개 목표와 디자인 패턴으로 구성됩니다. 지적장애·자폐 학생에게 WCAG만으로 남는 장벽을 확인하는 데 씁니다. 굵은 글씨는 COGA의 목표와 패턴 이름이고, 그 뒤는 앱에 적용한 질문입니다.

**목표 1. 무엇인지, 어떻게 쓰는지 이해하도록 돕기**

- [ ] **화면의 목적을 분명히 하기:** 각 화면이 무엇을 하는 곳인지 첫눈에 알 수 있는가?
- [ ] **일관된 시각 디자인 쓰기:** 버튼 모양, 색, 위치가 모든 화면에서 같은가?
- [ ] **각 단계를 분명히 하기:** 지금 무엇을 해야 하는지 단계마다 알려 주는가?
- [ ] **조작 요소와 쓰임을 분명히 보이기:** 누를 수 있는 것과 아닌 것이 구별되는가?
- [ ] **도움이 되는 아이콘 쓰기:** 아이콘이 익숙한 의미로 쓰이고, 글자나 음성과 함께 제공되는가?

**목표 2. 필요한 것을 찾도록 돕기**

- [ ] 중요한 정보와 주요 버튼이 쉽게 눈에 띄는가?
- [ ] 처음으로, 이전으로 같은 이동 방법이 분명한가?

**목표 3. 분명하고 이해하기 쉬운 내용 쓰기**

- [ ] **분명하고 모호하지 않은 언어:** 문장이 쉽고 하나의 뜻으로만 읽히는가?
- [ ] **암시된 내용 설명하기:** 비유나 돌려 말하는 표현 없이 직접적으로 말하는가?
- [ ] **전경이 배경에 묻히지 않게 하기:** 글자와 버튼이 배경 무늬나 그림에 가려지지 않는가?

**목표 4. 실수를 피하고 고칠 수 있도록 돕기**

- [ ] 잘못 누른 것을 쉽게 되돌릴 수 있는가?
- [ ] **내용이 바뀌면 알려 주기:** 화면이 바뀌거나 무언가 저장, 전송되었을 때 알려 주는가?

**목표 5. 집중하도록 돕기**

- [ ] **너무 많은 내용 피하기:** 한 화면에 꼭 필요한 내용만 있는가?
- [ ] **미디어를 짧게 나누기:** 긴 음성이나 영상이 짧은 부분으로 나뉘어 있는가?
- [ ] 방해가 되는 움직임, 소리, 팝업이 없는가?

**목표 6. 기억에 의존하지 않게 하기**

- [ ] 앞 화면에서 고른 것을 기억하지 않아도 다음 화면을 진행할 수 있는가?
- [ ] **기억이나 인지 능력에 의존하지 않는 로그인:** 교사 인증이 비밀번호 기억에만 의존하지 않는가?

**목표 7. 도움과 지원 제공하기**

- [ ] **복잡한 정보와 과제에 대안 내용 제공:** 어려운 활동에 그림, 시범, 쉬운 버전이 있는가?
- [ ] 도움을 요청하는 방법이 언제나 같은 자리에 있는가?

**목표 8. 적응과 개인화 지원하기**

- [ ] **내용이 움직이거나 바뀌는 시점을 학생이 조절:** 자동 재생, 자동 넘김을 학생이 멈추거나 끌 수 있는가?
- [ ] 학생에게 맞게 모드, 글자 크기, 소리 등을 바꿀 수 있는가?

**실제 사용자와 검증하기**

COGA는 인지·학습장애가 있는 사람을 연구, 설계, 개발 과정과 사용성 검사에 참여시키라고 권고합니다.

- [ ] 인지·발달장애 학생이 실제로 앱을 쓰는 모습을 관찰하고, 막힌 지점을 기록해 고쳤는가?

출처: [W3C COGA (w3.org/TR/coga-usable)](https://www.w3.org/TR/coga-usable) · [COGA 디자인 가이드 개요](https://w3c.github.io/wai-coga/coga-draft/guide/overview) · [COGA 요약](https://www.w3.org/TR/2020/WD-coga-usable-20201211/summary.html)

## 학생 개인정보 (교육부 학습지원 소프트웨어 필수기준)

교육부는 개인정보보호위원회와 협의해 2025년 12월 30일 학습지원 소프트웨어 선정기준을 발표했습니다. 필수기준은 「개인정보보호법」상 반드시 지켜야 하는 사항이며, 하나라도 충족하지 못하면 사용할 수 없습니다.

**먼저 적용 대상인지 확인**

- [ ] 학교 교육과정 운영에 쓰면서 학생 개인정보를 수집·이용·제공하는가? 그렇다면 적용 대상이며, 학교장이 기준 충족을 확인하고 학교운영위원회 심의를 거쳐야 합니다. (「초·중등교육법」 제29조의2, 2026.3.1. 시행)
- [ ] 교사가 수업 준비나 행정 업무를 위해 학생 개인정보 처리 없이 쓰는 경우는 적용 대상이 아닙니다. 학생 기록을 저장하지 않는 체험용 모드는 이에 해당하는지 따로 판단합니다.

**필수기준**

① 최소처리원칙 준수

- [ ] 개인정보가 최소한으로 수집되는가?
- [ ] 개인정보 수집·이용 목적이 기재되어 있는가?
- [ ] 개인정보 수집 항목, 보유기간 등이 기재되어 있는가?

② 개인정보 안전조치 의무

- [ ] 개인정보 안전성 확보에 필요한 조치 사항이 기재되어 있는가? (접근 권한, 교사 계정 인증 등)

③ 열람·정정·삭제·처리정지 절차

- [ ] 학생과 보호자가 열람, 정정, 삭제, 처리정지를 요구할 수 있는 절차가 안내되어 있는가?

④ 만 14세 미만 아동의 개인정보 보호

- [ ] 만 14세 미만 학생이 쓰는 경우, 법정대리인 동의 절차를 갖추었는가?

⑤ 보호책임자 / 제3자 제공 / 위탁 등

- [ ] 개인정보 보호책임자 관련 정보가 안내되어 있는가?
- [ ] 개인정보 제3자 제공에 관한 정보가 기재되어 있는가? (필요시)
- [ ] 개인정보 위·수탁 정보가 기재되어 있는가? (필요시, 예: Google Firebase 등 외부 서비스 이용)

**확인 방법**

필수기준 대부분은 '기재되어 있는가'를 묻습니다. 그래서 앱의 실제 동작과 함께, 위 내용을 담은 개인정보 처리 안내문이 있는지, 안내문과 실제 저장 항목이 일치하는지를 같이 확인합니다.

## 종합 판정표

법적 기준인 KWCAG 2.2와 교육부 필수기준은 적용되는 항목이 하나라도 미충족이면 '개선 필요'입니다. UDL과 COGA는 통과 기준이 아니라서, '장벽 남음' 항목과 그 장벽을 겪는 학생을 기록해 개선 순서를 정하는 데 씁니다.

| 영역 | 내용 | 항목 수 | 충족 또는 반영 | 해당 없음 | 판정 |
| --- | --- | --- | --- | --- | --- |
| KWCAG 2.2 (필수) | ①\~④ 검사항목 | 33 |  |  |  |
| WCAG 2.1·2.2 AA (보완) | ①\~④ 보완 기준 | 17 |  |  |  |
| WCAG AAA (선택) | ②③ 선택 기준 | 8 |  |  |  |
| UDL 3.0 참여 | 지침 7\~9 | 13 |  |  |  |
| UDL 3.0 표상 | 지침 1\~3 | 12 |  |  |  |
| UDL 3.0 행동과 표현 | 지침 4\~6 | 11 |  |  |  |
| 교육부 필수기준 | ①\~⑤ | 9 |  |  |  |

COGA 22개 항목은 판정 대신 '장벽 남음' 목록을 따로 적어 개선 계획에 씁니다.

**개선 순서**

1. 교육부 필수기준 미충족 항목 (충족하지 못하면 학교에서 사용할 수 없음)
2. KWCAG 2.2 미충족 항목 (법적 웹 접근성 기준)
3. WCAG AA 보완 기준 미충족 항목
4. UDL·COGA에서 장벽이 남은 항목 중, 실제 학생 관찰에서 막힘이 확인된 것
5. WCAG AAA 선택 기준
